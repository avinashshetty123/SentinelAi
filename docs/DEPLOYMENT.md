# Deployment

The target is: **backend and PostgreSQL on Render**, **frontend on Vercel**. Both deploy from a GitHub repository containing this monorepo.

## 0. Push to GitHub

```bash
git add -A && git commit -m "SentinelAI"
git remote add origin https://github.com/<you>/sentinelai.git
git push -u origin main
```

Before pushing, check that no secrets are tracked:

```bash
git ls-files | grep -E "(^|/)\.env($|\.)" | grep -v example
```

This must print nothing.

## 1. Backend and database on Render

1. Open the Render dashboard and go to **New → Blueprint**. Select the repository; Render reads `render.yaml`. It creates:
   - `sentinelai-db`: managed PostgreSQL, free plan.
   - `sentinelai-api`: a Docker web service built from `backend/Dockerfile`, with health check `/health`.
2. When prompted, set the `sync: false` secrets:
   - `GROQ_API_KEY`: your Groq key (optional).
   - `CORS_ORIGINS`: your Vercel URL, for example `https://sentinelai.vercel.app`. Fill this in after step 2 if you don't know it yet.
   - `CORS_ORIGIN_REGEX` (optional): matches preview deployments, for example `^https://sentinelai-[a-z0-9-]+-<team>\.vercel\.app$`.
3. Deploy. On every start the container runs `alembic upgrade head`, then starts a single Uvicorn worker.
4. Find `ADMIN_API_TOKEN` (generated by the blueprint) under the service's **Environment** tab. Operators enter it on the frontend **Settings** page.
5. Verify the deployment:
   - `https://<service>.onrender.com/health` returns `{"status":"ok"}`.
   - `/api/v1/health/ready` returns `{"status":"ready"}`.
   - `/docs` serves OpenAPI.

**Auth choice for a public demo.** The blueprint defaults to `AUTH_MODE=token`. To let judges use the app without a token, set `AUTH_MODE=open` **and** `ALLOW_OPEN_MODE_IN_PRODUCTION=true`. The app refuses to start in open mode in production without that explicit acknowledgement. Anyone can then use your Groq quota within the rate limits, so keep `GROQ_REQUESTS_PER_MINUTE` low.

**Notes:**
- `DATABASE_URL` is wired from the database with `fromDatabase`. `postgresql://` URLs are normalized to `postgresql+asyncpg://` automatically. For an external URL that needs TLS, `?sslmode=require` becomes `?ssl=require`.
- Free web services sleep when idle, and the first request after sleep can take tens of seconds. The UI shows "timed out — try again" and the WebSocket reconnects automatically.
- Free-plan limits (database expiry, hours, memory) are set by Render and change over time; check Render's current pricing page. Use a paid instance and database for anything beyond a demo.
- Keep **one instance**. Rate limiting, the WebSocket hub and the demo runner are in-process.

**Manual Render setup without the Blueprint:**
- Create a PostgreSQL database.
- Create a Web Service with Runtime **Docker**, Root Directory `backend` and Health Check Path `/health`.
- Set the environment variables listed in `render.yaml`.

## 2. Frontend on Vercel

1. In Vercel, choose **Add New → Project**, import the repository, and set **Root Directory** to `frontend`. The framework is detected as Next.js.
2. Add the environment variable for Production and Preview:
   - `NEXT_PUBLIC_API_URL = https://<service>.onrender.com/api/v1`
3. Deploy. Next.js 16 and Node 22 are used; `package.json` declares `engines.node >= 22.12`.
4. Copy the Vercel URL into Render's `CORS_ORIGINS`. Save, and Render redeploys automatically.
5. Open the site and check **System health**. The database should be *Connected*, the WebSocket *Live* and Groq *Active*. If token mode is on, enter the token under **Settings** first.

`NEXT_PUBLIC_*` values are compiled into the browser bundle, so **never** put `GROQ_API_KEY` or `ADMIN_API_TOKEN` in Vercel.

## 3. Local production-like run

```bash
cp backend/.env.example backend/.env    # add GROQ_API_KEY if desired
docker compose up --build               # UI on :3000, API on :8000, Postgres on :5432
```

## Database migrations

- **Automatic:** migrations run on container start (`RUN_MIGRATIONS_ON_START=true`).
- **Manual:** run `cd backend && DATABASE_URL=... alembic upgrade head`.
- **Rollback:** run `alembic downgrade -1`. Check the migration first; downgrades drop tables.

## Secret management

| Secret | Where it lives |
|---|---|
| `GROQ_API_KEY` | Render environment (`sync: false`), or the local `backend/.env` (git-ignored) |
| `ADMIN_API_TOKEN` | Generated by Render, or any random string of 24+ characters (`python -c "import secrets;print(secrets.token_urlsafe(32))"`) |
| Database credentials | Managed by Render; injected through `fromDatabase` |

To rotate a secret, change it in the Render dashboard; this triggers a redeploy. After rotating the operator token, re-enter it in the UI.

## Hosting requirements

| Service | Requirements |
|---|---|
| Backend | About 256–512 MB RAM. The classifier is pure Python; scikit-learn isn't installed at runtime. Python 3.12 (Docker image `python:3.12-slim`). |
| Database | PostgreSQL 15 or later. Tested on 17. |
| Frontend | Any Next.js 16 host. A standalone Docker image is also provided (`frontend/Dockerfile`). |
